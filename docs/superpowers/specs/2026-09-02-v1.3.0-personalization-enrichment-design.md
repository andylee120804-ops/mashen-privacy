# 麻神祈福 v1.3.0 个性化与内容增强设计

> 状态：已确认 | 日期：2026-09-02 | 目标：通过华为应用市场审核（审核指南 3.5 项「功能不足/使用场景有限」）

## 背景

应用已两次因「审核指南第 3.5 项 功能不足」被拒（v1.1.0、v1.2.0）。当前功能线为：选神像 → 叩拜 → 祈福 → 祝福语，外加求签 / 还愿 / 牌运记录 / 成就 / 黄历 / 排行榜。审核员认为「使用场景有限」，本质是三条短板：

1. **广度不够**：祈福到记录的闭环之外，缺少日常高频工具（木鱼、运势查询）。
2. **频次不够**：用户除了祈福当天，没有每天打开的理由。
3. **个性化不足**：界面固定，无法按用户习惯定制。

v1.3.0 围绕「**麻将人的随身祈福工具箱**」定位，一次到位补齐上述三点，并把「**今日牌运**」做成灵魂功能。

## 设计目标

- 把底部导航从「固定 4 Tab」升级为「**祈福固定 + 我的固定 + 中间可自定义**」，让用户自由选择入口与顺序，实现个性化显示。
- 新增「电子木鱼」高频解压工具、「运势·黄历」每日查询工具、「财神历·神诞」年度内容。
- 「运势·黄历」同时支持 **黄历 + 星座 + 属相** 三维查询，并**醒目标注「适不适合打牌」与幸运数字**，紧扣麻将祈福主题。
- 全部新增功能为纯本地静态/确定性生成数据，不新增云端依赖、不改 Cloud DB schema、不新增云端部署。

## 架构变更：动态可配置 Tab + 统一入口管理

### Tab 结构

```
祈福 🀄（固定 Tab 0）│ 中间可配置 1~3 个 Tab │ 我的 🧧（固定最后一个 Tab）
```

- **祈福** 固定第一个，**我的** 固定最后一个（我的页承载定制入口本身，不可隐藏，避免用户把自己锁在设置之外）。
- 中间 Tab 由用户在「我的」页开关 + 排序，最多 3 个（底部导航最多 5 项，超出自动回落为「我的」页 MenuItem）。
- 被关掉 Tab 的入口不消失，自动降级为「我的」页 MenuItem，功能永不丢失。

### 可配置入口池（7 项）

| id | 图标 | 标题 | 目标页 | 默认是否 Tab |
|---|---|---|---|---|
| qiuqian | 🎋 | 求签 | QiuQian | ✅ Tab 第 1 |
| muyu | 🪵 | 电子木鱼 | MuyuPage（新增） | ✅ Tab 第 2 |

默认 Tab 效果 = `祈福 | 求签 | 木鱼 | 我的`（沿用「还愿换木鱼」的决定，但还愿现在可一键开回 Tab）。

## 新增 / 改造功能详细设计

### 1. 界面定制（统一入口管理）

**配置模型**（存储于 preferences，新增 key）：

```typescript
interface EntryConfig {
  id: string          // 入口 id，对应入口池
  enabled: boolean    // 是否作为底部 Tab 显示
  order: number       // 排序权重（越小越靠前）
}
// 持久化为 [{id, enabled, order}] 数组
```

**新增 `EntryConfigVM`**（`@Observed`，独立文件）：
- `enabledTabEntries()`：返回 `enabled=true` 的入口，按 `order` 升序，供 MainTabs 渲染。
- `allEntries()`：返回全部 7 入口（含默认值合并），供 MyPage 渲染定制列表。
- `toggle(id)` / `move(id, dir)`：开关与上移/下移；`toggle` 打开时若已满 3 个 Tab，提示「最多 3 个 Tab」并拒绝。
- `isEnabled(id)`：查询单入口是否启用。

**MainTabs 改造**：
- `Tabs` 内固定渲染 Tab 0（祈福）与最后一个 Tab（我的），中间按 `enabledTabEntries()` 条件渲染 `TabContent`。
- Tab 标题 / 图标从配置读；`tabTitles` / 图标数组改为由配置动态生成，`currentTab` 索引按实际渲染顺序映射。

**MyPage 改造**：
- 新增「界面定制」区块：遍历 `allEntries()`，每行 = 图标 + 标题 + `Toggle`（Tab 开关）+ `↑`/`↓` 按钮。
- 「我的入口」列表：遍历 `allEntries()` 按 `order` 排序，点击 `pushUrl` 到对应页面。

**双模进入（统一外壳 EntryShell）**：7 个入口页统一为 `@Component export struct` 内容组件（**不含返回头**）。Tab 模式由 MainTabs 直接渲染内容组件（无返回头）；「我的」页「我的入口」列表统一 `pushUrl('pages/EntryShell', { entryId })`，由新增 `@Entry @Component struct EntryShell` 渲染对应内容组件 + 返回头 + 标题。

- 入口 id → 组件映射集中在 EntryShell：`qiuqian→QiuQianPage`、`muyu→MuyuPage`、`fortune→FortuneAlmanacPage`、`wishwall→WishWallPage`、`calendar→ShenDanCalendarPage`、`leaderboard→LeaderboardPage`、`encyclopedia→EncyclopediaPage`。
- 既有 `@Entry` 页 Leaderboard / EncyclopediaPage 改为 `@Component export struct` 内容（去掉各自内部返回头），返回头统一由 EntryShell 提供；MyPage 现有 `pushUrl('pages/Leaderboard')` / `pages/EncyclopediaPage` 改走 EntryShell。
- `main_pages.json` 移除 Leaderboard / EncyclopediaPage 两个 @Entry 页，新增 EntryShell。

### 3. 电子木鱼（MuyuPage，新增）

- 界面：居中一个木鱼（emoji 🪵 + 木槌动效），点击一次 = 敲一下。

    | 弱 | 不宜下注，易破财 | 橙 `#e67e22` |
    | 忌 | 忌打牌，今日避赌 | 红 `#e74c3c` |
  - ✅ 宜（3 条 chips，如「宜打牌 / 宜纳财 / 宜会友」）
  - ❌ 忌（3 条 chips，如「忌借贷 / 忌争执 / 忌赌局」）

**数据生成（确定性，避免手写数千条）**：见下文「数据生成算法」。

### 5. 财神历·神诞（ShenDanCalendar，新增）

- 静态神诞日历：列出 5 路财神（赵公明/萧升/曹宝/陈九公/姚少司）及常见财神/吉日的神诞日期（本地静态数据）。
- 支持收藏/标记关注的神诞（收藏项排前，持久化）。不做倒计时（农历换算需引入日历库，超出本轮范围）。
- 本轮**不做系统通知提醒**（通知权限未声明、后台任务复杂度高），提醒留待后续版本，见「非目标」。

### 6. 还愿心愿墙入口迁移

- WishWall 保持 `@Component export struct WishWallPage`（无需改 @Entry）；作为 Tab 由 MainTabs 直接渲染，作为「我的入口」经 EntryShell 进入。
- `@StorageLink('wishFulfilledAt')` 保持全局 AppStorage，从任何入口进入都能在还愿成功后刷新，无需改动。

## 数据流

```
祈福 Tab（固定）
├─ 黄历卡 DailyAlmanac（既有）
├─ 五神阵 → 开始祈福 → NameCard
│    └─ 场景选择（新增 SCENE_DEFS）→ PrayerCard → BlessingCard（按场景出祝福）
│
可配置 Tab（1~3 个，由 EntryConfigVM 驱动 MainTabs 条件渲染）
├─ 求签 / 木鱼 / 运势·黄历 / 还愿 / 财神历 / 排行榜 / 百科（任一可进 Tab）

我的 Tab（固定）
├─ 牌运汇总卡（既有）
├─ 今日运势速览卡（新增）→ FortuneAlmanacPage
├─ 成就徽章（既有）
├─ 界面定制（新增）→ EntryConfigVM 读写 preferences
└─ 我的入口列表（按用户 order 排序，pushUrl('pages/EntryShell') 到各页面）
```

所有新增页面的持久化走 preferences（复用 EnrichViewModel 的 `getPreferences` 模式）；运势数据由确定性 PRNG 生成，不存储、不上云。

## 数据生成算法（运势确定性）

**目标**：同一日期 + 同一属相/星座，结果恒定可复现；不手写数千条文案。

```typescript
// 简单可复现的伪随机（LCG / mulberry32）
seed = hash(`${dateStr}|${dim}|${index}`)
// dateStr = 'YYYY-MM-DD'；dim = 'zodiac' | 'shengxiao'；index = 0..11
```

每次（每日每维度）产出：

| 字段 | 来源 |
|---|---|
| 综合星级 1-5 | seed 取模 |
| 牌运档（旺/吉/平/弱/忌） | 按权重抽签（旺 20% / 吉 25% / 平 25% / 弱 20% / 忌 10%），保证有好有坏有起伏 |
| 宜 3 条 | 从宜池无放回抽 3 |
| 忌 3 条 | 从忌池无放回抽 3 |
| 幸运数字 2 个 | 1-9 无放回抽 2 |
| 幸运颜色 1 个 | 从色池抽 1 |

**文案池**（各几十条，含麻将祈福特色）：
- 宜池：宜打牌 / 宜纳财 / 宜签约 / 宜会友 / 宜表白 / 宜出行 / 宜投资 / 宜考试 / 宜搬家 / 宜开业 …
- 忌池：忌赌局 / 忌借贷 / 忌争执 / 忌远行 / 忌冲动消费 / 忌熬夜 / 忌贪大胡 / 忌心浮气躁 …
- 星座总评模板池 + 各星座关键词（爱情/事业/财运三行短评各一套池）

内容量：12 星座 + 12 属相 × 任意日期，全部由「池子 + seed」生成，数据文件只存池子与表（集中在 model 层 1 个文件内）。

**黄历任意日期查询**：`ALMANAC_TABLE` 现有 30 条按 `dayOfYear % 30` 轮换；新页将查询日期代入 `dayOfYear`，与祈福页黄历卡同源、结果一致。

## 错误处理

- preferences 读写失败：沿用 EnrichViewModel 的 try/catch + console.error 模式，UI 用默认值兜底（入口配置缺失时回落到默认 4 Tab）。
- 界面定制「开启第 4 个 Tab」被拒：Toast 提示「最多 3 个 Tab」。
- 运势/黄历数据生成失败：确定性算法无外部依赖，理论上不失败；PRNG 输入做边界保护（日期非法时回落到今天）。
- 新增页面云函数/网络不可用（仅还愿/排行榜涉及）：沿用 CloudService 的 `.catch` 静默兜底，不阻断本地功能。

## 测试

- 构建：debug + release 均通过。
- 界面定制：开关任一入口，底部 Tab 即时增删；排序即时生效；关掉后从「我的」页仍能进入；重启后配置保留。
- 运势·黄历：同一天同一属相/星座反复进入结果一致；换日期结果变化；星座/属相选择持久化。
- 木鱼：连续点击计数正确、跨日清零、音效与震动触发、DUCK 不打断后台音乐。
- 场景矩阵：7 场景可选，BlessingCard 祝福语随场景变化。
- 还愿：从「我的」页 MenuItem 与（若开启）Tab 两路进入均能还愿成功并刷新。
- WCAG 对比度：新增 UI 文字/图标按 `#1a1a0a`（及弹窗 `#241f12`）对照规则文件 `common/wcag-contrast.md` 校验，牌运五档颜色逐档算对比度。
